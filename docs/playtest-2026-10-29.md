# Playtest of the in-browser demos, 2026-10-29

The owner: "please playtest the website. I particularly want to make sure the games are playable as when i press
space the browser scrolls. There should also be tiger gorilla and mower mayhem demos." Later the same day: "the
website should also have touch controls for the games so they can be played on a mobile without a keyboard" and
"all games on the website should be single level demos".

Fixes: [D-21](decisions.md#d-21-the-game-keeps-the-keyboard-while-it-has-focus-owner-2026-10-29) (keys),
[D-22](decisions.md#d-22-touch-controls-owner-2026-10-29) (touch pad) and
[D-23](decisions.md#d-23-single-level-demos-tiger-gorilla-and-mower-mayhem-demos-owner-2026-10-29) (demos).
Screenshots: [screenshots/playtest/](screenshots/playtest/).

## How it was run

- **Browser**: headless Chromium 156 (snap) driven over the DevTools protocol by Puppeteer, with real key and
  touch events (`Input.dispatchKeyEvent` and `Input.dispatchTouchEvent`), so the browser's own default actions
  (scrolling) happen as they would for a person. Smooth scrolling was off, so `scrollY` reads settle at once.
- **Pages**: every game page. It was served locally from `_site/` and checked before the push, then checked on
  the live site after it.
- **Desktop** (1280 x 800):
  - Load the page and record `scrollY`. Click "Play the demo" and press Space every 50 ms while it loads.
  - Wait until the screen holds still for 3 s (the title), or 150 s for an animated title.
  - Press Space to start, then for 25 s hold each movement key from the page's controls for 0.8 s in turn, with
    a Space tap after every third hold. Read `scrollY` every 100 ms during each hold, and compare the screen
    before and after every press.
  - Then press Arrow Down/Up, Page Down/Up, End, Home, Backspace, Space and Arrow Right.
  - Then Pause (the screen must freeze, and Page Down must scroll the page), Resume, and Space (no scroll).
  - Tab (focus must leave the game, then Page Down scrolls) and Escape (focus released, then Space scrolls).
  - Full screen (the wrapper with the screen and pad) and Space in it, then Restart.
- **Phone**: iPhone 12 emulation (390 x 844, touch, coarse pointer).
  - Tap Play, wait for the title, and tap the big START button.
  - For 20 s hold each direction of the on-screen pad for 0.8 s. Every third time, also hold START with a second
    finger.
  - Slide a held finger 300 px off the pad and lift it: nothing may stay held.
  - Then turn to landscape (844 x 390).
- **Errors**: console errors, page errors and failed requests were collected throughout.

The movement keys: Gold Master O, P, Q, A; Antigravity S, R, S, O, S, P (its ship falls upward onto the lethal
ceiling unless S is held, so S is weighted); Wordris O, P, A; WOLF O, P.

## The bug, before the fix (live site, old `player.js`)

- **Space after the automatic pause scrolled the page by 700 px.** The game pauses itself when the window loses
  focus (another window, the address bar, developer tools); the screen keeps focus, but JSSpeccy unbinds its
  keyboard while paused. Most likely the owner's case. With the fix, the key resumes the game and the page stays
  put.
- **During the load** (not measured; reasoned from the code): the old player set no loading state, so the
  script had nothing to press against. Focus sat on the disabled Play button, and JSSpeccy's keyboard was not
  yet bound, so a key pressed then reached the page. The fix focuses the screen before loading.
- **Tab could not leave the game**: focus stayed on the screen and Page Down did nothing. JSSpeccy blocks every
  key, Tab included. Escape did nothing either.
- **After Play the top of the screen sat 3 px above the window.**
- **Full screen took only JSSpeccy's box.**
- With the screen focused and the game running, Space, the arrows and Page Down did *not* scroll: JSSpeccy blocks
  them while it is bound. The gaps were all around that state.

## Problems with individual games

- **Antigravity**: the first second is unforgiving (see above). That belongs to the game, not the site.
- **Wordris**: the title animates, so automated checks cannot wait for it to settle. People are unaffected.
- **Tiger Gorilla**:
  - The milestone tape tried (M2) has a title menu on 1 to 5 (start, keyboard, Kempston, Sinclair, redefine).
    Those keys are not on its page's controls list, so they are not on its touch pad (D-22). Space starts the game, so the pad still works.
  - If the menu should be on the pad, add the keys to the game's controls in its media kit and republish.
- **Mower Mayhem**: the M1 tape that was considered steers like a tank (O/P turn, Q/A speed). The page describes
  the release's direct drive, so the single-level demo build of the release is the better demo (D-23).

**END OF DEMO in the browser.** Scripted real-time play cannot finish a level, so two games were driven
frame by frame instead. The live page's emulator was held when the player started it, then stepped with
`runFrame`. The game's own recorded inputs were replayed from the frame its code starts, and its state was
read with the vendored worker's `peek`. Every frame the game ran was the live site's `demo.bin` in the live
page's JSSpeccy, with no pokes:

- **Wordris** used its bot's cold run (`demo/build/verify-m3/demo-bot-cold-keys.json`, recorded on
  `6cdcf48a…`). `letters_cleared` reached 31 at frame 554, and END OF DEMO came up at frame 583
  (`HARNESS_state` 3, `demo_ends` 1). It then returned to the title and started level 1 again, never level 2.
- **Tiger Gorilla** used `demo/recipes/demo-level1-end.json`. LEVEL COMPLETE came up with an unseen bonus of
  2000 and a score of 3600, then END OF DEMO ("THE FULL GAME HAS 12 LEVELS IN 3 ZONES"), then the DEMO title.

Gold Master, Antigravity, WOLF and Mower Mayhem were not taken to END OF DEMO in the browser. Their bots are
closed-loop Python policies, with no recorded key track for the current demo tape. Each game repository's
demo verify proves its card.
